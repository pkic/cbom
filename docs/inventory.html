Inventory and CBOMs

A CBOM and a cryptographic inventory are related but distinct. This page describes the difference between the two and the relationship between them, so that the role of a CBOM within a wider inventory is clear.

Two artifacts, two scopes

A CBOM is a bill of materials for a single artifact: a structured, machine-readable description of the cryptography that a specific component contains or uses, produced at a defined point in time. It is analogous to a software bill of materials.

A cryptographic inventory is an organization-wide record of the cryptography in use across systems, aggregated from many sources and maintained continuously. It exists to support risk management, compliance, and migration planning across the estate.

How they relate

CBOMs are a primary input to a cryptographic inventory. An inventory is assembled by collecting, normalizing, and correlating CBOMs from across the estate, together with data from other sources such as network and configuration discovery. The CBOM is per-component and point-in-time; the inventory is cross-component and longitudinal.

The role of profiles

For CBOMs produced by different tools and vendors to be aggregated into a coherent inventory, they must be comparable. A profile defines the attributes each CBOM is required to contain, and, together with normalization at the adapter, ensures that values are expressed consistently. This comparability is a precondition for reliable aggregation. Without it, an inventory assembled from heterogeneous CBOMs cannot be relied upon. See Challenges and Formats.

Multiple data sources and lifecycle stage

A cryptographic inventory typically combines CBOM data, which is frequently implemented or configured, with runtime discovery, which is observed. The lifecycleStage attribute allows the inventory to distinguish declared capability from observed use, rather than conflating the two. See Lifecycle Data.

Relationship to SBOM and HBOM inventories

A cryptographic inventory is generally maintained alongside software and, where relevant, hardware inventories. CBOMs are consumed together with SBOMs, and in some cases Hardware Bills of Materials, so that cryptography can be related to the components and hardware that implement it. This relationship determines, for example, whether a change requires a software update or a hardware replacement.

In summary: a CBOM is a per-component, point-in-time disclosure; a cryptographic inventory is the organization-wide, continuously maintained aggregate constructed from many CBOMs and other sources. Profiles and normalization are what make that aggregation reliable.
