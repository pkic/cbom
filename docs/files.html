Files & how to run

Every machine-readable artifact behind the example, plus the commands to reproduce the pass/fail verdicts.

Artifacts

FileWhat it is
profile-interface-disclosure.mdProse profile spec (product + per-interface rules)
profile-interface-disclosure.rules.jsonMachine-readable rules, incl. appliesTo version range
mapping-cyclonedx-spdx.mdFull requirement → format mapping
cbom-pass.cyclonedx.jsonConforming example CBOM (CycloneDX 1.7)
cbom-fail.cyclonedx.jsonNon-conforming example — omits the management interface
validate_cbom.pyVersion-aware validator
versioning-and-legacy-cboms.mdHow the project handles older CBOM files

Run the validator

# conforms (CycloneDX 1.7)
python validate_cbom.py cbom-pass.cyclonedx.json profile-interface-disclosure.rules.json

# does not conform — fails product rule P2 (no management interface)
python validate_cbom.py cbom-fail.cyclonedx.json profile-interface-disclosure.rules.json

# JSON output, for wiring into a CI gate
python validate_cbom.py cbom-pass.cyclonedx.json profile-interface-disclosure.rules.json --json

See the version bands

# make a legacy (1.6) and an unsupported (1.5) copy, then validate each
python - <<'PY'
import json
b = json.load(open("cbom-pass.cyclonedx.json"))
for v in ("1.6", "1.5"):
    b["specVersion"] = v
    json.dump(b, open(f"cbom-{v}.json", "w"))
PY
python validate_cbom.py cbom-1.6.json profile-interface-disclosure.rules.json   # legacy -> warn, still evaluates
python validate_cbom.py cbom-1.5.json profile-interface-disclosure.rules.json   # unsupported -> refused
