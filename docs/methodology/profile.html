The profile: Interface Disclosure Baseline

This profile is product-independent. It states structural requirements — which categories of interface must exist, and what each must disclose — and therefore applies to any product. It does not reference a specific product or interface instance.

A profile must not bind a rule to a specific product or interface. An earlier draft incorrectly required interfaceId to equal "nginx-https". Rules instead constrain the set of interfaces and the attributes of each interface.

Two directions of use

A single attribute table is applied in two directions.

Two rule groups

Product-level rules (constraints on the set of interfaces)

#RequirementLevelConstraint
P1Declare at least one cryptographic interfaceMUSTminInterfaces: 1
P2Declare at least one management interfaceMUSTminInterfacesOfType: {management, 1}

Per-interface rules (applied to every interface)

#AttributeLevelNotes
I1protocolMUSTTLS, SSH, IPsec, and similar
I2protocolVersionMUST
I3keyExchangeMUSTregistry algorithm identifier
I4encryptionMUSTbulk or AEAD algorithm
I5authenticationMUSTcertificate signature (TLS) or host key (SSH)
I6endpointRolesMUSTat least two endpoints
I7interfaceTypeMUSTfrom the controlled vocabulary
I8lifecycleStageMUSTsee Lifecycle Data
I9implementationPurlSHOULDPackage URL of the implementing library. Withholdable.
A CBOM conforms if and only if the carrier format is accepted, every product-level MUST rule holds, and every declared interface satisfies every per-interface MUST rule. interfaceId is an instance label chosen by the producer and is not constrained by the profile.

Derived evaluations such as post-quantum posture are deliberately not profile attributes. They are computed by an external policy from the disclosed facts, because the criteria on which they depend change over time. See Policy Evaluation.

Disclosure states

An attribute with no value may be missing for different reasons, and version 0.2 of the profile distinguishes them. Following the 2026 SBOM minimum elements, a producer states whether the information is unknown to it or is being withheld.

OutcomeMeaningEffect on a MUST rule
valueA value was supplied and checked against the constraint.Passes if valid.
withheldThe producer holds the information and declines to publish it.Passes only where the rule is marked withholdable.
unknownThe producer does not have the information.Fails, but is reported as unknown rather than absent.
undeclaredNeither a value nor a marker was supplied.Fails.

An unknown value does not satisfy a MUST rule, because the requirement has not been met. It is still reported separately from an undeclared one: the first records a limit of the producing process, the second records that the question was not addressed. In this profile only I9 is withholdable, on the basis that a producer may decline to publish a library version while still meeting the disclosure objective. A procurement profile might permit no withholding at all. See Challenges and Demo.

Conformance pipeline

The validator applies four stages in sequence. The content stages are evaluated only if the format stage accepts the CBOM.
