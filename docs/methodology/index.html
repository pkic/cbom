Overview

A Cryptography Bill of Materials (CBOM) profile states what a CBOM must contain to support one decision, for one reader, and how to check that it does. The working group sets out its methodology for writing such profiles in three publications. These pages are their companion on the web: each page explains a chapter, or part of one, with diagrams, worked examples and checks you can run.

PKIC CBOM Profiles WG companion to Release 1 CycloneDX 2.0 (1.6 and 1.7 read as legacy) not normative
Meeting this for the first time? Read the Introduction first. It follows one product, its CBOM and one question a buyer asks about it, from start to finish, and takes about five minutes. The rest of this overview is easier to use once you have read it.

How these pages relate to the publications

The publications are the authoritative text. They are written to be read in order and to be cited, so they define each term before using it and keep their examples short. These pages explain the same material for a reader who wants to see it working: they show the example records, run the validator, and draw the diagrams that a publication cannot.

The sidebar follows the publications. Each group is one publication, and each page title starts with the number of the chapter it explains, so that you can move between a page and the text it explains. Every page also says at the top which chapter it explains, and links to the publication. Where a page and a publication differ, the publication applies.

The examples are the same in both. The Keycloak identity server runs through the methodology from the first chapter. The examples gallery adds OpenSSH, a VPN gateway and the remote-administration system built from them, a substation, IoT sensors and the records of the application-domain drafts. The working group site has the application-domain documents, which apply the methodology to one sector each.

Suggested reading paths

You can read the pages in sidebar order, which is the order of the publications, or follow the route below that suits your role. Each route assumes you have read the Introduction.

If you areRead in this orderWhy this route
Producing CBOMs
a vendor, or a build or release team		 Model → Profiles and rules → Depth families → Confidentiality → Formats → Older CBOM files → Examples
  • Model: the terms used throughout.
  • Profiles and rules: what a profile requires you to declare.
  • Depth families: which profile in a family to aim for first, and how to move on to a more detailed one.
  • Confidentiality: which information you publish openly, which you release only under agreement, and how a profile allows for that.
  • Formats: where each attribute is written in a CycloneDX or SPDX document.
  • Older CBOM files: what happens to CBOMs you have already published when a format or profile version changes.
  • Examples: a record close to your product, to start from.
Requiring and reading CBOMs
an operator or buyer assessing a supplier, an auditor or regulator		 Challenges → Starting from a use case → Profiles and rules → Conformance → Depth families → Confidentiality → Vulnerabilities → Context pointers → Regulation
  • Challenges: why the CBOM data supplied today is hard to use.
  • Starting from a use case: what a profile can be written to require.
  • Profiles and rules and Conformance: what a passing result confirms, and what it does not. Conformance matters most for this role.
  • Depth families: how to write a requirement that a supplier can meet now, with a date for meeting a more demanding profile later.
  • Confidentiality: why a conforming CBOM can still have information withheld, and how to ask for the more complete version.
  • Vulnerabilities: how to use a CBOM when an advisory is published, and why a passing result says nothing about whether the cryptography is safe.
  • Context pointers: how a CBOM points to its SBOM, the vendor's vulnerability statements and the advisory feed.
  • Regulation: whether a conforming CBOM gives you the facts a regulation asks for.
Writing or approving a profile
working group members, sector bodies		 Model → Writing a profile → Starting from a use case → Profiles and rules → PQC migration → Governance
  • Model: the terms used throughout.
  • Writing a profile: the procedure.
  • Starting from a use case: the first stage of the procedure.
  • Profiles and rules: an example of the result.
  • PQC migration: one profile taken through the procedure from start to finish.
  • Governance: what happens after a profile is published.
