# Example CBOMs

This folder holds the methodology's example CBOMs. Every record is CycloneDX 2.0 unless it sits in `legacy/`, which holds CycloneDX 1.7 documents. The companion SBOMs, VEX documents and guidance that the records cite are in `context/`. The results of evaluating policies against the records are in `results/`.

There are two kinds of example. A conforming record shows what a complete answer looks like for one kind of subject. A failure variant is a copy of a conforming record with one thing broken, so that it fails exactly one rule. You can use the failure variants to check that a validator reports the rule you expect.

To browse the examples as readable pages, with each failure variant's fix explained, open the [examples gallery](https://pkic.github.io/cbom/methodology/examples.html).

Every verdict below is checked by the test suite (`bash tests/run-profile-tests.sh`). This file is generated by `python3 tools/build_examples_catalogue.py` from the test cases. Do not edit it by hand: change the tests and run the script again.

To check a record yourself:

```bash
python3 docs/methodology/validate_cbom.py \
    docs/methodology/examples/cbom-openssh-10.0p2-product.cdx.json \
    docs/methodology/profile-pqc-migration.rules.json
```

Add `--with <file>` for each record that the example cites, where a case below lists one.
