CBOM Profiles

A CBOM profile is a defined subset of mandatory attributes for one objective — a minimum bar, not exhaustive coverage. This site explains the profile methodology through a worked example: an nginx web server, its CBOM in CycloneDX 1.7, checked against a small, product-independent profile.

PKIC CBOM Profiles WG illustrative CycloneDX 1.7 / ECMA-424 not normative

Why profiles

A cryptographic bill of materials (CBOM) records what cryptography a product uses, where, and under what conditions. Reporting every cryptographic call in a large product buries the items that matter for a given decision. A profile fixes that: it names the handful of facts a decision needs, so a CBOM can be checked automatically for "did you disclose enough?" A single CBOM can satisfy several profiles at once.

The example profile here — Interface Disclosure Baseline — asks a product to declare its cryptographic interfaces, including the one used to configure it, and to describe each. It never names a specific product or interface, so it applies to any TLS/SSH/IPsec-terminating system. nginx is only the subject that makes it concrete.
