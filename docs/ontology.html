CONCEPT

Ontology: node, edge, asset

The methodology depends on three terms. Distinguishing them is what allows a profile to describe connections rather than only algorithms.

The three terms

TermDefinitionIn the example
Cryptographic relationship (edge / interface)The location at which cryptography is applied between parties. It is not itself a cryptographic asset.The TLS 1.3 session; the SSH session.
Endpoint (node)A party to a relationship.client (browser or admin) and server (nginx or host).
Cryptographic assetAn algorithm, protocol, certificate, or key used by the relationship.X25519, AES-256-GCM, the RSA certificate, OpenSSL.

Significance of the distinction

Post-quantum migration analysis concerns connections, not inventory alone. The statement that an organization uses a given algorithm somewhere is of limited value compared with the statement that a specific connection between two services still negotiates a classical group. The first is a property of a node; the second is a property of an edge. Conflating the two prevents accurate analysis. For this reason the working group adopted cryptographic relationship (edge) and endpoint (node) as the core terms, and defines interfaceType and endpoint roles as attributes of the relationship rather than of any single algorithm.

Neither CycloneDX nor SPDX currently provides a first-class object that represents the relationship. Both approximate it by attaching relationship attributes to a protocol asset. Providing such an object is the objective of the working group's first-class attributed-edge model. See Challenges and Formats.
